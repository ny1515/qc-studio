# QC Studio

QC活動の記録を7つの工程に沿って整理し、編集できるPowerPoint・Excel資料を作成するブラウザーアプリです。QC7つ道具・新QC7つ道具・層別を使った図表も、活動資料の付録として出力できます。

GitHub Pagesの公開先（予定）：[https://ny1515.github.io/qc-studio/](https://ny1515.github.io/qc-studio/)

## 使い方

1. 「新しいQC活動を作成」で、空の活動を作成します。「サンプル」から架空データで操作を試すこともできます。
2. 左側の工程を選び、活動内容・測定データ・要因・対策などを入力します。
3. 必要に応じて「QC道具」から道具を追加し、入力データと解析結果を確認します。
4. 右上の「保存」で、このブラウザーに記録します。保存は手動です。`Ctrl + S`（Macでは`⌘ + S`）も使えます。
5. 「PowerPoint」「Excel」で資料をダウンロードします。資料の出力前にも保存処理を行います。

サンプル活動とサンプル道具は架空の内容です。名前を変更しても、サンプルの表示は維持されます。

### 活動の7工程

テーマの選定 → 現場把握 → 要因の解析 → 対策の立案 → 効果の確認 → 標準化と管理の定着 → 反省と残された課題

各工程で入力のヒントと未入力項目を確認できます。入力項目の充足は、活動の完了や効果の証明を意味するものではありません。

### 作成できる15種類の道具

| 区分 | 道具 |
| --- | --- |
| QC7つ道具 | パレート図、特性要因図、チェックシート、ヒストグラム、散布図、管理図、グラフ |
| 新QC7つ道具 | 親和図法、連関図法、系統図法、マトリックス図法、マトリックス・データ解析法、アロー・ダイヤグラム法、PDPC法 |
| 補助的な整理方法 | 層別 |

管理図はI-MR管理図とp管理図、マトリックス・データ解析法は標準化したデータの主成分分析に対応します。親和図のグループや連関図の矢印は、利用者が入力した内容を使います。

道具ごとにタイトル、関連工程、メモ、資料に含めるかどうかを設定できます。未完成の道具を下書きとして残す場合は、「PowerPoint・Excelの資料に含める」のチェックを外してください。選択した道具に必要な入力が不足していると、資料出力時に修正箇所を案内します。

## 保存とデータの取り扱い

- 活動データは、利用中のブラウザーのIndexedDBに保存します。アカウント登録は不要です。
- このアプリには、活動の入力内容をサーバーへ送信する処理はありません。サイトやプログラムの読み込みにはインターネット接続を使います。
- チーム共有、ログイン、別端末・別ブラウザーとの自動同期には対応していません。
- ブラウザーのサイトデータを削除すると、保存した活動も失われます。端末の変更やブラウザーのデータ削除に備えて、JSONバックアップを保存してください。
- 別の端末やブラウザーへ移す場合は、「JSONバックアップ」で保存し、移行先の「読み込み」から取り込みます。読み込みは元の活動を上書きせず、新しい活動を作成します。JSON読み込みの上限は4 MBです。
- 同じ活動を複数のタブで開き、別のタブから更新した場合は、古い内容での上書きを防ぐため保存が止まります。手元の入力をJSONで保管してから、保存版を開き直してください。

空欄と数値の0は区別します。未測定の項目を0で埋めず、測定結果が0の場合に「0」を入力してください。

## PowerPoint・Excel出力

PowerPointの本文、表、図形、グラフは編集できます。7工程の活動資料に加え、「資料に含める」を選んだ道具を付録として出力します。

ExcelのQC道具の解析表・図は、出力した時点の結果です。**Excel上で道具の入力データを変更しても、解析結果は自動更新されません。** 道具の入力の変更と再計算はQC Studioで行い、再出力してください。主成分分析や日程計算も同じ扱いです。

管理図の管理限界は、入力した基準データから推定します。規格限界とは異なります。相関や対策前後の数値変化だけで、因果関係や統計的な有意差は判断できません。測定条件と現場の事実を確認して、資料を仕上げてください。

## 開発・確認

Node.js 22以上と、pnpm 11.25.0を使用します。以下のコマンドは、リポジトリのルートで実行してください。

```sh
pnpm --dir web install --frozen-lockfile --ignore-scripts
pnpm --dir web build
pnpm --dir web test
node --test tests/model.test.mjs tests/qc-tools.test.mjs
```

`web/build.mjs`はブラウザー向けの配布ファイルを`docs/`に生成します。`docs/`はビルド時に作り直すため、直接編集せずソースを変更して再ビルドしてください。

ビルドした画面を手元で確認するには、次を実行します。

```sh
node web/dev-server.mjs
```

ブラウザーで[http://localhost:4318/qc-studio/](http://localhost:4318/qc-studio/)を開きます。このサーバーは静的ファイルの確認用で、活動データの保存処理はブラウザー内で行います。公開URLとローカルの確認URLでは保存領域が別になるため、活動データを移す場合はJSONバックアップを利用してください。

### ソース構成

| パス | 内容 |
| --- | --- |
| `public/` | 7工程とQC道具の画面、スタイル、共通の画面処理 |
| `lib/` | 活動モデル、QC道具の定義・解析、共通の図形配置 |
| `web/src/` | IndexedDB用API、ブラウザー内のPowerPoint・Excel生成 |
| `web/tests/` | ブラウザー保存、競合防止、出力などのテスト |
| `web/build.mjs` | ブラウザー用バンドルと配布ファイルの生成 |
| `docs/` | GitHub Pagesで配信するビルド結果 |

公開版に内部専用の`@oai`ランタイムは含まれません。ブラウザー用の公開依存ライブラリで資料を生成します。

## GitHub Pagesへの反映

1. ソースを変更し、ビルドとテストを実行します。
2. 生成した`docs/`をソースと一緒に`main`ブランチへコミットしてpushします。
3. リポジトリの **Settings → Pages** で、**Deploy from a branch**、ブランチ **main**、フォルダー **/docs** を指定します。

配布ファイルは`/qc-studio/`での公開を想定しています。ビルドで生成する`docs/.nojekyll`も含めて配置してください。Pagesの配信が更新されたら、公開先URLで画面とダウンロードを確認します。
